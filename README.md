# Landbot Experience Library

Ways a conversation can look when it does not have to look like a chatbot.
Each one is a working Landbot bot or voice agent you can try right now, in your
browser, without an account.

Every brand is invented. No order, booking or payment is real.

## Try them

Open a link and go through it yourself. Web chats are made for phone width,
and they work on desktop too.

## Use it with Claude

Give Claude the link to this repo and ask what you need:

> Read https://github.com/landbot-org/experience-library and tell me which
> experience fits a dental clinic that wants to book appointments.

> Using the Experience Library, explain how the bot-to-human handoff works.

[`AGENTS.md`](AGENTS.md) tells Claude what is here and what it can and cannot
do with it, so you do not have to explain the library first.

## Rebuild one in your own Landbot account

An experience is buildable when its folder has a `RECIPE.md`: what it is for,
what it captures, what to customize, the whole flow, and the setup it needs.
Give it to your agent:

> Build experience 01 from https://github.com/landbot-org/experience-library
> in my Landbot account, following its RECIPE.md.

Your agent builds it with the plugin's own components, not by copying the demo's
code, so what you get is maintained and yours to change.

> **First recipe in progress:** [01 · WhatsApp lookalike](experiences/01-whatsapp-lookalike/RECIPE.md).
> It is a draft until its PENDING sections are filled. The rest have no recipe
> yet and can be tried live only.

### What you need

Trying, recommending and explaining an experience needs nothing. Rebuilding one
needs all of these:

1. **Your own Landbot account with the Bots API enabled.** The plugin acts with
   your API token, so the bot is created in your account, not ours.
2. **The Landbot plugin** ([landbot-org/landbot-ai-skills](https://github.com/landbot-org/landbot-ai-skills)).
   It is what lets your agent create the bot, wire the flow, set up its AI
   agents and apply its style. Without it, an agent can read this repo but
   cannot build anything in Landbot.
3. **The Custom Code feature on your Landbot account**, for the look. These
   experiences get their look from Custom JS, and Landbot serves Custom JS only
   to accounts with Custom Code. Without it the flow still works, but it looks
   like a plain chat.

Install the plugin in the agent you use:

| Agent | Install |
|---|---|
| Claude Code | `claude plugin marketplace add landbot-org/landbot-ai-skills` then `claude plugin install landbot@landbot-skills` |
| Claude desktop app | Customize › Plugins › Add marketplace › `landbot-org/landbot-ai-skills` › install **landbot** |
| Codex | `codex plugin marketplace add landbot-org/landbot-ai-skills` then `codex plugin add landbot@landbot-skills` |
| Cursor | `git clone https://github.com/landbot-org/landbot-ai-skills` then `landbot-ai-skills/scripts/install.sh cursor` |

The first time, the plugin asks you to connect your Landbot account. It keeps
your token in your keychain or your shell. Never paste it into a chat, an issue
or a file. For a guided setup, or if your account does not have the Bots API
yet, see [landbot.io/skills](https://landbot.io/skills).

## What is in this repo

| Path | What it holds |
|---|---|
| [`catalog.json`](catalog.json) | The source of truth: every experience with its category, channel, brand, live link and export status |
| [`AGENTS.md`](AGENTS.md) | The entry point for AI agents |
| `experiences/<slug>/` | One folder per experience: a README, a screenshot and, for web chats, the published channel style in `channel/` |
| [`scripts/pull-public`](scripts/pull-public) | Refreshes each web chat's `channel/` from its live share URL, and stops if it finds anything that looks like a secret |
| [`scripts/build-readmes`](scripts/build-readmes) | Regenerates every experience README and the tables above from `catalog.json` |
| [`scripts/check-links`](scripts/check-links) | Checks that every live link answers |
| [`scripts/check-boot.mjs`](scripts/check-boot.mjs) | Opens every web bot in headless Chrome and checks it starts. A share link answers even when its bot is broken, so this is the check that counts |

## Contributing

To add or change an experience:

1. Edit its entry in [`catalog.json`](catalog.json). The catalog is the source
   of truth.
2. Pull the published style, regenerate the docs and check the links:

   ```bash
   ./scripts/pull-public && ./scripts/build-readmes && ./scripts/check-links && node scripts/check-boot.mjs
   ```

   Do not edit the tables in this README or the experience READMEs by hand:
   `build-readmes` overwrites them.
3. Do not commit tokens, webhook URLs, integration keys or anything that
   identifies a real customer. This repo is public.
